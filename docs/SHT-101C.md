# 새 삼성 SHT-101C (1.0.12)

이 모델은 이전 SHT-101C 코드와 리소스를 복구하지 않고 새로 작성했습니다. 새 모듈 ID는 `homenet_sht101c`이며 예전 삼성 확장의 ID·클래스·리소스를 포함하지 않습니다. 기존 코콤·현대 기능은 검증된 1.0.8 JAR의 239개 클래스를 그대로 보존합니다.

## 1.0.12 본체 수정

틀 뒤로 돌출되던 컨트롤러·모니터 케이스 두 개를 제거하고 장착판 뒤를 평평하게 정리했습니다. CRT와 거치대를 가리던 본체 면을 실제 개구부로 나눴습니다. 화면은 검은 베젤·두 단계 경사면·4:3 유리로 구성하고 카메라 영상의 표시 위치도 같은 유리에 맞췄습니다.

거치대는 위·아래 받침이 이어지는 파인 곡면이며, 본체 덮개의 이음선과 버튼 돌출을 낮췄습니다. 명암·밝기 손잡이는 실제 홈 안에 들어가고 통풍구는 정면이 아닌 아래쪽 면을 향합니다. 본체 로고·마크도 조정했습니다. 수화기, 수화기 안테나와 수화기 조작화면 텍스처는 승인된 1.0.11과 동일합니다.

검사는 실제 메시의 삼각형을 대상으로 화면 안쪽 아홉 지점에 유리가 가장 앞에 보이는지, 거치대 바닥이 파여 있는지, 통풍구가 아래를 향하는지 확인합니다. 생성된 모든 위치·법선이 유한한지도 검사합니다. 이미지나 스크린샷은 만들지 않습니다.

## 외형

사용자가 올린 바닥 위 측면·정면·수화기 앞면 사진과 선으로 표시한 비율 사진을 함께 기준으로 삼았습니다. 안테나를 제외한 파란 내부 영역 가로는 정확히 0.5블록입니다. 바깥 틀은 약 0.543083 × 0.395631블록입니다. 안테나는 블록 밖으로 나올 수 있습니다.

밝은 아이보리 본체, 별도 장착판, 양 끝 둥근 덮개, 좌측 충전 거치대, 후크·충전 접점·스피커 슬롯, 중앙 기능 버튼 열, 숫자키, 하단 통풍구, 들어간 흑백 CRT 화면을 새로 구성했습니다. 수화기 뒷면과 앞면을 구분하고 앞면에 오목한 수화부·검은 타원 숫자키·검은 기능키·충전 접점을 배치했습니다. 같은 줄 버튼의 앞면 높이와 돌출 깊이는 같습니다. 곡면·모서리는 실제 메시와 법선으로 음영을 계산합니다.

수화기 안테나는 수직이고 본체 가운데 안테나는 처음 설치하면 접힌 상태입니다. 본체 안테나는 조작 화면에서 펼 수 있습니다. 외부 배선, 사진 배경, 변색·오염과 광고는 모델에 포함하지 않습니다. 동작 사진·스크린샷은 생성하지 않습니다.

## 방식과 연결

- 크리에이티브 `SAMSUNG SHT-101C` 탭에서 본체를 설치합니다.
- 본체 화면의 `BUS / STAR`로 방식을 선택합니다. 수화기를 거치하고 통화를 종료해야 변경할 수 있으며 변경 시 이전 경비실 연결을 해제합니다.
- BUS는 삼성 디지털 BUS 규격의 경비실기와만 연결합니다. 코콤·현대 BUS로 우회하지 않습니다. 동·호 번호는 경비실에서 지정합니다.
- STAR는 같은 단지의 STAR 경비실 통화 경로를 사용하며 본체에서 동·호 번호를 입력할 수 있습니다.
- 도어카메라·도어폰은 홈 링커로 본체 → 세대 외부기기 순서로 연결합니다. 홈 링커로 경비실을 연결하지 않습니다.
- 단지가 다른 기기는 연결·호출·영상·메시지·문열림을 허용하지 않습니다.

**현재 제공 기기 제한:** 기존 삼성 SHT-5500S는 모델 전용이므로 BUS 교환기 역할을 새로 부여하지 않았습니다. BUS 경비실 통화에는 기능이 구현된 삼성 BUS 경비실기가 필요합니다. 본체의 BUS 경로는 삼성 BUS 시험 교환기로 검증하고 STAR 경로는 기존 실제 STAR 경비실기로 검증합니다.

## 수화기와 통화

본체 화면의 수화기 부분을 누르면 무선수화기를 받습니다. 수화기를 손에 들고 우클릭하면 앞면 조작 화면이 열립니다. 웅크리고 우클릭하면 전원을 전환합니다. 수화기가 들려 있을 때 **본체 화면의 빈 수화기 자리 또는 벽에 설치된 본체의 빈 거치대를 클릭**하면 인벤토리의 해당 수화기를 찾아 다시 겁니다. 선택한 손에 수화기가 없어도 됩니다. 다른 본체의 수화기는 받아들이지 않으며 거치 시 통화를 종료합니다.

무선 범위는 같은 단지 안의 32블록입니다. 충전·배터리는 게임용으로 단순화하여 약 30분을 사용하고 재거치하면 충전된 수화기를 받습니다. 실물 최초 12시간 충전과 실제 RF 간섭은 재현하지 않습니다.

설명서 조작 순서:

| 동작 | 순서 |
|---|---|
| 본체에서 경비실 발신 | 본체 경비실 → 무선수화기 통화 |
| 수화기에서 경비실 발신 | 수화기 경비실 |
| 경비실·현관·공동현관 착신 | 무선수화기 통화 |
| 현관 감시·통화 | 본체 문/열림 → 무선수화기 통화, 또는 수화기 문/열림 |
| 공동현관 문열림 | 공동현관 통화 중 문/열림 |
| 본체 → 수화기 내선 | 본체 호출 → 수화기 통화 |
| 수화기 → 본체 내선 | 수화기 호출 → 본체 스피커 |
| 통화 종료 | 수화기 통화 또는 다시 거치 |
| 메시지 | T 또는 입력란 클릭 → 입력 → Enter |

현관 착신을 15초 안에 받지 않으면 종료합니다. 영상은 흑백이며 카메라의 컬러 영상을 흑백으로 표시합니다. 밝기·명암을 조절할 수 있습니다. 게임 안의 양방향 통화는 채팅 메시지로 구현합니다.

## 전화·기억·암호

외부 전화망에 접속하지 않습니다. 같은 단지의 다른 새 SHT-101C에 등록된 자택 전화번호로 연결하는 게임 내 전화입니다.

- 자택 번호: 본체 메모리 → 스피커 → 번호 → 메모리.
- 본체 암호: 본체 메모리 → 경비실 → 두 자리 → 메모리.
- 수화기 암호: 수화기 메모리 → * → # → 같은 두 자리.
- 고정장치 암호: 본체 메모리 → 보류 → 같은 두 자리.
- 암호 확인: 수화기 메모리 → 본체 호출. 세 암호가 같으면 일치 안내.
- 단축번호 저장: 메모리 → 단축키 → 전화번호 → 메모리. 본체는 3–9·*·#, 수화기는 0–9를 사용합니다.
- 단축번호 발신: 본체 스피커 또는 수화기 통화 → 메모리 → 단축키.
- 원터치 저장: 본체 메모리 → 소방·경찰·병원 버튼 → 번호 → 메모리.
- 발신: 본체 스피커 또는 수화기 통화 → 번호. 입력이 끝나면 발신하며 #으로 즉시 발신할 수 있습니다.
- 재다이얼: 본체 재다이얼 → 수화기 통화. 수화기 재발신으로 국선 통화로 전환할 수 있습니다.
- 보류: 본체 보류, 재통화는 수화기 통화.
- 국선 선택: 본체 메모리 → 재다이얼 → 0/1 → 메모리. 통화 중 *은 전자식 선택입니다. 실제 전화국 펄스 신호는 재현하지 않습니다.
- 채널전환은 저장되며, ▲·▼는 통화 중 수화 음량 또는 대기 중 착신 음량을 바꿉니다.

## 경보

비상 버튼과 레드스톤 감지 입력을 제공합니다. 아래 접점은 화재, 위는 비상, 동쪽은 가스, 나머지는 방범입니다. 방범은 방범 설정 상태에서만 감지합니다. 열린 문이 있으면 방범·외출을 설정하지 않으며 외출 후 1분 뒤 방범이 설정됩니다.

시험 → 1/2로 화재/가스 내부 경보를 시험합니다. 시험은 경비실·전화에 통보하지 않습니다. 실제 경보는 30초 내부 경보 후 호환 경비실과 저장된 *·# 번호로 순서대로 통보하며 각각 세 번씩 시도합니다. 게임 내 자동통보는 경보·자택 번호 메시지로 표현합니다. 112·113·119는 자동통보 번호로 등록하지 않습니다.

경보정지는 표시를 남기고 통보를 멈춥니다. 복귀로 초기화하며, 정지 후 5분이 지나면 자동 복귀합니다.

## 검증

전용 게임 테스트 9개로 BUS/STAR 호출, 실제 STAR 경비실 연동, 현관 영상·통화·15초 종료, 빈 거치대의 네 방향 클릭, 수화기 소유권·범위·단지 제한, 전화 기억·보류, 암호·경보·자동통보·저장을 검사합니다. 실제 클라이언트 검사에서는 홈 링커 패킷, 수화기 분리·조작, 현관 응답, 한글 입력·양방향 메시지와 빈 거치대 클릭 후 상태 갱신을 확인합니다.

## 개발

```bash
source /workspace/homenet-setup/activate.sh
python tools/sht/model.py
python tools/sht/validate.py
gradle -b sht101c.gradle build
gradle -b sht101c.gradle -Psht.runDir=/tmp/sht-check-new runGameTestServer
python tools/sht/package.py
```

실제 클라이언트 검사는 X 디스플레이에서 `gradle -b sht101c.gradle -Psht.clientTest -Psht.runDir=/tmp/sht-client-new runClient`로 실행합니다. 화면 캡처는 하지 않습니다. `.device-baseline/base.jar`는 SHA-256 `f523a392449c967bdca61081f9425ed0cb706f7d2d03096b4964d732f8695593`으로 고정한 기존 배포본이고 `dev.jar`는 해당 배포본의 개발용 매핑입니다.

최종 산출물 `build/sht101c/release/qwertys_homenet-1.0.12.jar` 하나로 교체합니다. 서버와 클라이언트 모두 기존 JAR를 제거하고 교체 후 재시작합니다. 별도 확장 JAR와 중복 설치하지 않습니다.
