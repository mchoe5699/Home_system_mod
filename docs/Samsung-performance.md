# 삼성 제품 렌더링 성능 수정

SHT-101C·SHT-102C와 공통 휴대장치·충전기에 적용합니다. 배포 파일명은 `qwertys_homenet.jar`입니다.

## 변경

- 곡면·경계선·버튼의 고정 형상을 상태별로 한 번 계산하고 여러 기기에서 공유합니다. 수화기 거치/들기와 안테나 상태는 각각의 형상을 사용합니다.
- 색상·표면 방향·깊이·텍스처 좌표가 모두 같은 평평한 직사각형만 합칩니다. 곡면·경계선과 화면 텍스처는 유지합니다.
- 정점 버퍼의 일괄 입력 경로를 사용하고 월드 조명과 발광 램프는 계속 반영합니다.
- 화면 밖 강제 렌더링을 해제합니다. 안테나와 기기 이동 오프셋을 포함하는 경계 상자로 화면 가장자리 잘림을 방지합니다.
- 충전기는 배터리·착신 등 상태가 바뀔 때 갱신합니다. 완충 대기 중 같은 상태의 패킷을 매초 반복하지 않습니다.
- 리소스를 다시 불러오면 형상 캐시도 비웁니다.

## 검증과 측정

아래 표는 첫 캐시 수정 때 실제 클라이언트의 같은 실행 환경에서 기존 계산 경로와 새 경로를 비교한 수치입니다. 캐시가 준비된 뒤 동일한 본체를 12회 처리한 측정이며 전체 게임 FPS를 뜻하지 않습니다.

| 항목 | 기존 | 수정 |
|---|---:|---:|
| 실제 정점 버퍼 입력 CPU 시간, 12회 | 약 927ms | 약 36ms |
| 형상 처리의 임시 Java 메모리 할당, 12회 | 약 41MB | 약 1.4KB |
| 본체 8개 상태의 고정 정점 합계 | 996,928 | 845,488 |

초기 캐시 생성 시간과 캐시 보관 메모리는 별도로 필요합니다. 처음부터 형상을 매 프레임 재생성하던 반복 비용을 제거한 것이며, 사용자의 장치·설치 대수·거리·통화 영상에 따라 실제 FPS 개선 폭은 달라집니다.

기존/수정 형상에 대한 위치·색상·표면 방향 비교, 캐시 재사용, 월드 조명과 발광 조명, 본체·휴대장치 형상, 실제 홈링커·수화기·통화·램프·18종 착신 영상 검사를 통과했습니다. 서버 기능 검사 34개를 통과했으며, 완충 대기·충전 진행·착신 시작/종료 갱신 검사를 포함합니다. 게임 화면이나 스크린샷은 생성하지 않았습니다.

## 불투명 벽 뒤의 기기 생략

이전 수정의 화면 밖 검사만으로는 시야 안에 있는 벽 뒤 기기의 정점 전달을 막지 못했습니다. 본체·안테나·거치 수화기 및 충전기 조립체의 실제 형상 경계와 이동 위치를 사용해 가림을 검사합니다. 불투명한 전체 블록에 가려지면 본체/충전기의 정점과 본체 영상 처리를 건너뜁니다. 유리·계단·나뭇잎 같은 부분 또는 투명 블록은 전체 가림으로 처리하지 않습니다.

판정은 짧게 재사용하며 카메라 위치나 형상 경계가 달라지면 다시 검사합니다. 같은 위치에서 벽을 설치하거나 제거한 결과는 최대 약 0.1초 뒤 다시 반영합니다. 일부가 보이는 기기는 계속 렌더링합니다. 통화·착신 등 서버 기능은 가림 여부와 관계없이 계속 동작합니다.

SHT-102C는 수화기를 들면 본체의 수화기 형상을 완전히 제거합니다. 검은 안테나의 펼친 길이와 접힌 가로 길이를 SHT-101C와 일치시킵니다.

벽 가림 검사를 포함한 서버 검사 35개를 통과했습니다. 실제 클라이언트에서 돌벽 뒤 본체·충전기 정점 전달이 0개이고 유리 너머 및 벽 제거 후 렌더링이 복구되는 것을 확인했습니다. SHT-102C의 완전히 빈 거치대와 두 안테나 상태의 길이 일치도 실제 형상에서 확인했습니다.
